# 資料投遞區（給供應端的檔案規則）

把從健保署官網抓到的**原始 HTML** 放進這裡並推送，GitHub Actions 會自動處理：
解析 → 更新 `docs/data/*.json` → 清空本目錄 → 重新發布網站。

處理跑在一般的 GitHub runner 上，不需要通過 Cloudflare——官網由你那端讀取，
這裡只做解析。

## 放哪裡

```
incoming/
├── topics/     共擬會議、醫療給付改善方案
└── drug/       藥品給付規定與法規公告（選用）
```

兩個目錄都是選用的，有什麼放什麼；沒放的那區會沿用既有資料，不會被清空。

## 要放什麼

**原始 HTML（頁面原始碼），不是 Markdown、不是 PDF、不是截圖。**

解析器讀的是 `section.fileDownload`、`span.fileType`、表格的 `<thead>` 這些
DOM 結構。轉成 Markdown 之後這些資訊已經被壓掉，無法還原。瀏覽器裡「檢視
網頁原始碼」或 `document.documentElement.outerHTML` 存下來的就是要的東西。

### `incoming/topics/`

| 專區 | 要抓的頁 |
|---|---|
| 共擬會議 | `lp-2771-1.html` 及其分頁 |
| | 上述表格每一列連到的 `cp-` 內容頁 |
| | **新位置的列表頁**（見下方說明） |
| 改善方案 | `np-2823-1.html` |
| | 其下子分類的 `np-` 頁 |
| | 子分類底下的 `cp-` 方案頁 |

### `incoming/drug/`（選用）

| 要抓的頁 |
|---|
| `lp-3258-1.html`，含分頁 `?pi=1&ps=60` 起算約 15 頁 |
| `np-2505-1.html`、`np-2506-1.html`、`np-2508-1.html`、`np-3397-1.html`、`np-2509-1.html`、`np-3420-1.html` |

### 共擬會議：兩棵樹，都要投

以下結構由 2026-10-25 的實際頁面確認，新位置代號已登錄在設定裡。

**舊樹**（`lp-2771-1`，自 114-03-28 起不再更新，但歷年資料仍在）

```
lp-2771-1.html            列表共 22 筆、每頁 20 筆，所以有 2 頁
  └── cp-…-2771-1.html    22 個「年度」頁（115年、114年…93年）
```

**新樹**（`np-3720-1`，現行位置）

```
np-3720-1.html            節點頁，底下掛 23 個年度節點
  └── np-…-1.html         年度節點（115年 np-4147、114年 np-3911、113年 np-3849…）
        └── cp-….html     該年度的會議頁
```

**關鍵：中間層不能跳過。** 專區歸屬是從 hub 沿連結走出來的，少了年度節點那一層，
底下的 `cp-` 頁就無法歸入，會全部落到 `unassigned`。

`lp-2771-1.html` 的**兩頁都要投**（`?pi=1`、`?pi=2`）：第 2 頁只有 94年、93年
兩筆，近年的全在第 1 頁。`ps` 參數無效（固定每頁 20 筆），照官網實際分頁存即可。

一個「年度」頁裝該年所有會議的議程與紀錄（例如 112年 那頁有 12 個附件），
所以資料集裡一筆項目＝一個年度，新會議上架會以「附件更新」呈現。

> ⚠️ 兩個目錄**不要混放**。藥品給付規定的解析器會把共擬會議的列表頁誤判成
> 法規公告，污染 `announcements.json`。

## 不要放什麼

**不要放附件檔案**（PDF／DOC／ODT 等會議紀錄、計畫書、問答集）。

資料集只記錄附件的檔名、類型、大小與官網連結，前端也是直接連到官網原始檔，
本站不轉存。

這一條很重要：**git 歷史是永久的**。附件一旦推進來，就算下一個 commit 刪掉，
檔案仍留在歷史裡，repo 會持續膨脹且無法回收。整批要的 HTML 通常只有數 MB，
附件則可能數百 MB。

處理時若偵測到非 HTML 檔案，Actions 會發出警告並列出檔名。

### 唯一的例外：藥品給付規定「整份帶走」PDF

這一份**要**，但不放 `incoming/`——它不是「附件連結」而是本站自存並對外提供的
資產：`docs/files/nhi-drug-rules-full-*.pdf` 是逐條給付規定查詢（網站主要功能）
的建置來源，由 `scraper/extract_rules.py` 切章拆條後產生 `rules.json`。

目前站上是 115.07.23 版。要更新時請另外告知，由處理端走單獨流程換檔重建，
不走投遞區——換版需要重跑抽取並核對條數，不適合混在自動流程裡。

## 檔名怎麼取

**不拘。** 處理時會自己從 `<link rel="canonical">`、`og:url`、或檔名裡的頁面
代號判斷每份檔案是哪一頁。用原始網址、用中文標題、用流水號都可以。

專區歸屬是從 hub 頁沿著連結走出來的，不是靠網址規則——改善方案的方案頁帶的
是子分類代號（如 `np-2824`）而非 hub 代號（`np-2823`），照網址比對會整批歸錯。

沒被任何 hub 連到的檔案會列在 Actions 的警告裡，不會被靜靜丟掉。

## 回執：`incoming/LAST_RUN.json`

**每次投遞前先讀這個檔。** 本 repo 公開，讀取不需要任何權杖：

```
https://raw.githubusercontent.com/TLAN1012/NHI-Rules/<分支>/incoming/LAST_RUN.json
```

`run_at` 為 `null` 代表還沒有過任何投遞（初始狀態），不是處理失敗。

這份檔案是雙方的信箱，記錄上一批處理的結果：

```jsonc
{
  "run_at": "...", "run_url": "...",              // 哪一次 Actions 執行
  "received": { "topics": { "html": 42, "non_html": [], "bytes": 1234567 } },
  "used":     { "meetings": { "hub_pages": 3, "child_pages": 38,
                              "items": 38, "attachments": 61 } },
  "unassigned": [ "cp-..." ],   // 收到但沒被任何 hub 連到，已略過
  "unreadable": [ "..." ],      // 判斷不出是官網哪一頁，已略過
  "problems": [ "..." ],        // 有值代表那次 run 失敗，資料沒有發布
  "notes":    [ "..." ]         // 不致失敗，但下次投遞可以改進的地方
}
```

`problems` 非空時整個 run 會失敗、網站不會更新，而且**投遞區的內容會被保留**
——修正後直接重推即可，不必重抓官網。`notes` 不影響成敗。

會被判定為 problems 的情況：

| 狀況 | 多半是什麼原因 |
|---|---|
| 收到 HTML 但沒有任何一頁被歸入專區 | 忘了附 hub 頁；歸屬是從 hub 沿連結走出來的 |
| 收到 hub 與子頁，卻解析出 0 筆項目 | 官網版型與解析器的假設不符 |
| 收到子頁，但附件一個都沒有 | 子頁版型不符，或投遞的其實是列表頁而非內容頁 |

最後一項值得特別說明：項目標題可以從 hub 的表格取得，**附件卻只能從子頁的
「檔案下載」區解析**。所以「有項目但附件全為 0」是版型對不上的真訊號，比
「0 筆項目」更早也更準地抓到問題。

## 推送之後

**推送到預設分支 `claude/nhi-drug-coverage-rules-14nnaf`。** 處理流程只在該分支
的 push 上觸發；推到其他分支（含 PR 分支）不會有任何反應。

處理完成後：

- `docs/data/topics.json`、`topic_changes.json`（及 `drug/` 有放時的公告資料）更新
- 本目錄的檔案被清空（`.gitkeep` 保留）
- 網站重新發布

處理結果（收到幾份、用了幾份、哪些沒歸入）會寫在那次 Actions 執行的摘要裡。

## 有話要說？

投遞相關的自動回饋走 `LAST_RUN.json`；**需要討論的事情走 `comms/`**
（一訊息一檔、只新增不修改，格式與用法見 `comms/README.md`）。

訊息與投遞一樣推到預設分支 `claude/nhi-drug-coverage-rules-14nnaf`——
`comms.yml` 只在該分支的 push 上觸發。

不要把說明文字塞進投遞區——`topics/` 與 `drug/` 會在每次處理後清空。

## 本機手動跑

```bash
python3 scraper/ingest_topics.py incoming/topics --out cache/topics
python3 scraper/build_topics.py cache/topics --out docs/data
```
